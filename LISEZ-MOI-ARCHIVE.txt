Yu-Gi-Oh! Collection Manager — V2 Rust
Archive du 2026-09-30, pour essai sur une autre machine.

CE QU'IL Y A DEDANS
  Application\ygo-ui.exe, ygo-cli.exe   les deux programmes, deja compiles
  crates\, assets\, Cargo.*             tout le code source
  *.ps1, LISEZ-MOI.md, README.md        les scripts et la documentation

AUCUNE DONNEE DE CARTE : pas de base de reference, pas de classeur, pas
d'image, pas de log, pas d'export. L'application part d'une page blanche.

DEMARRER, SANS RIEN INSTALLER
  .\Lancer.ps1
  (ou double-cliquer Application\ygo-ui.exe)

Au premier demarrage, l'application construit sa base de reference : environ
35 Mo a telecharger, moins d'une minute. Elle s'installe dans Application\bdd\,
a cote de l'executable. Le dossier Application\ est deplacable tel quel.

RECOMPILER
  .\Compiler.ps1
Il faut Rust (https://rustup.rs). La version de la chaine d'outils est
epinglee par rust-toolchain.toml (1.95.0) et s'installe toute seule au premier
appel.

CE QUI MANQUE, ET POURQUOI
  tests\   ecarte volontairement de cette archive : les fixtures d'oracle sont
           des extraits de cartes figes (11 Mo), et vous avez demande une
           archive sans donnees de carte.
           Consequence : .\Verifier.ps1 ne passera pas -- les tests d'oracle
           ont besoin de ces fixtures pour seulement compiler. La compilation
           de l'application, elle, ne les touche pas (verifie).
  target\  se refait a la compilation.

A SAVOIR
  Reprendre-Une-Collection.ps1 sert a reprendre une collection existante
  depuis une autre installation ; sur une machine neuve, il n'a rien a
  reprendre. Les chemins cites dans les commentaires des scripts sont des
  exemples, pas des chemins en dur.
